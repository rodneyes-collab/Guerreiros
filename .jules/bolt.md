## 2024-05-14 - Isolate `elapsedTime` Timer State
**Learning:** `App.tsx` has a `setInterval` that updates `elapsedTime` in `useStore` every second when a match is active. `App.tsx` and `MatchView.tsx` both consume `elapsedTime` via `useStore(state => state.elapsedTime)`, meaning the ENTIRE `App.tsx` and `MatchView.tsx` components re-render every single second during a match. This is a massive performance bottleneck specific to this architecture since Zustand hooks cause the reading component to re-render.
**Action:** Extract the timer logic (and its UI display in `MatchView.tsx` and anywhere else it is used purely for display) into a dedicated child component (e.g., `TimerTracker` and `MatchTimerDisplay`). Or simply avoid selecting it in large parent components unless necessary, using imperative `useStore.getState().elapsedTime` when possible.
